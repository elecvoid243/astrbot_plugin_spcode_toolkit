# Authenticated manual host file management

`POST /spcode/host-file-manage` accepts `{path: absolute, operation: "rename" | "trash", new_name?: string}`. It uses WebUI extension authentication and host account permissions, independently of Agent modes, loaded projects and worktrees. It does not register an Agent tool. `worktree` and `ref` are rejected. Only existing regular files are supported; rename accepts a bare filename and stays in the same directory, rejecting existing destinations.

Success requires `data.renamed === true` with `path` and `new_path`, or `data.deleted === true` with `trashed === true` and `path`. Errors include `invalid_body`, `invalid_param`, `path_unsafe`, `path_not_found`, `not_a_file`, `file_exists`, `permission_denied`, and `operation_failed`. Paths identify actual resolved targets. This binding does not lock arbitrary external filesystem writers.

Both legacy `POST /spcode/file-remove` and `DELETE /spcode/docs` retain their project/path validation and now use the same validated `trash_file` operation. Failure returns `trash_failed` without a permanent-delete fallback. The extension adapter reads JSON for POST, PATCH and DELETE, preserving explicit session/worktree context. No recursive directory or batch management is added.


Windows recycling requires Windows 8 or later, a local fixed drive and the declared Windows-only `pywin32` dependency. The adapter uses `IFileOperation` with mandatory `FOFX_RECYCLEONDELETE`, raises a COM cancellation from `PreDeleteItem` when recycling is not offered, and requires successful item status with a non-null recycled item plus a non-aborted operation. Missing dependencies, unsupported locations, aborted operations and native recycling failures are errors; the `send2trash` legacy/`SHFileOperation` path is never called. Other platforms retain the existing native `send2trash` capability.

Host rename uses Windows no-replace rename, Linux `renameat2(RENAME_NOREPLACE)` or macOS `renamex_np(RENAME_EXCL)`. A destination created concurrently is not replaced. Missing functions or unsupported kernel/filesystem flags fail without a replace-capable fallback. This guarantee covers destination collisions; it does not lock arbitrary external writers changing the source path.

Native contracts: [Microsoft recycle-only flag](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags), [pre-delete cancellation](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem), [actual recycled item](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-postdeleteitem), [Linux exclusive rename](https://man7.org/linux/man-pages/man2/rename.2.html), and [Apple rename flags](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/stdio.h).
